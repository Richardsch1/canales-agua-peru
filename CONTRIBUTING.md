# Contribuir

Se aceptan correcciones respaldadas por fuentes oficiales y mejoras del código. Usa información institucional pública y ejemplos ficticios. No publiques datos de ciudadanos, credenciales ni documentos personales.

## Añadir o corregir una entrada

1. Confirma en una fuente institucional el contacto, ámbito, finalidad y condiciones. Prioriza una ficha actual; contrasta otra fuente cuando haya discrepancias.
2. Documenta en `sources` la URL, el título y una paráfrasis breve de la evidencia. No copies páginas o formularios completos.
3. Establece `checkedOn` en la fecha en que efectivamente revisaste esa entrada. No cambies fechas de otras entradas ni renueves la revisión solo porque una URL responde HTTP 200.
4. Si la página bloquea acceso automatizado, documenta el límite y revisa el texto oficial disponible. No inventes un contacto para llenar un vacío.
5. Comprueba si el canal es para orientación, reporte operativo o recurso documental; no atribuyas competencia por ubicación.
6. Añade pruebas cuando cambien condiciones o el contrato. Ejecuta `npm run check` y `npm test`.
7. Abre un PR que explique el problema, el cambio final y lo que realmente verificaste.

Los dominios nuevos, prestadores adicionales o cambios de política de privacidad requieren revisar el contrato, los filtros y sus pruebas. La versión inicial no contiene un directorio rural validado de JASS o municipalidades.

## Desarrollo

Node.js 22 o 24, sin dependencias externas. Mantén mensajes en español y las consultas ordinarias sin red. Las comprobaciones HTTP deben continuar siendo opcionales, sin redirecciones ni actualización automática de evidencias. Las contribuciones se reciben bajo MIT.

## Colaboración

Respeta a las comunidades y a otras personas que contribuyan. No se aceptan acoso, discriminación, difusión de información privada, contactos fabricados o métricas inventadas. El mantenedor puede retirar contenido que incumpla estas pautas. Solicita un canal privado sin divulgar datos cuando una situación lo requiera.
